# ETH 驱动移植指南

> 面向实现 `mr_eth_ops_t`
> 的平台开发者。公共接口、帧长和应用侧用法见 [ETH 驱动](eth.md)。

| 项目   | 说明                                                       |
|--------|------------------------------------------------------------|
| 功能宏 | `MR_USE_DRIVER_ETH`，可选 `MR_USE_DRIVER_ETH_STREAM`       |
| 操作表 | `mrX/include/mrX/drivers/eth/mr_eth.h` 中的 `mr_eth_ops_t` |

## 1. 移植边界

以太网控制器从硬件接收帧或将帧发出。移植要保证两件事：上层只能收到完整的帧，每块缓冲区在后端使用期间只由后端访问。公共层负责设备类型、MAC/MTU
和长度校验，以及 Wait 对象的生命周期。后端负责 MAC、PHY、时钟、引脚、IRQ、DMA
和在途帧的使用权。应用负责帧缓冲池、软件队列、重试和 RX 补充。

将平台实现放在 `mrX/arch/<vendor>/<target>/platform/drivers/eth/`。用 `priv`
保存平台私有状态，例如 MAC 寄存器、PHY
接入信息、描述符及帧关联。芯片资源归属、初始化与中断分发应在目标平台文档中单独定义。控制器自带 DMA 时可以直接由 ETH 后端管理，ETH 公共层无需 `MR_USE_DRIVER_DMA`。

## 2. 操作表与设备生命周期

以下四个基础成员为必需回调。

| 基础成员                | 实现责任                                                                                                                      |
|-------------------------|-------------------------------------------------------------------------------------------------------------------------------|
| `configure(drv, config)` | 应用 MAC、MTU、速率、双工、回环、流控和校验和卸载。速率为 `MR_ETH_SPEED_OFF` 时关闭端口。成功返回 0，失败返回负错误码 |
| `link(drv, link)`         | 读取物理链路状态、实际速率、双工和流控，成功时写入 `*link`；统计字段由公共层填写。链路断开属于正常查询结果 |
| `read(drv, buf, size)`  | 交付一帧，`size` 是容量，无帧返回 0                                                                                           |
| `write(drv, buf, size)` | 接受一帧，`size` 是长度，返回接受的帧长或负错误码                                                                             |

setup 先初始化 Wait，再将保存的配置交给 `configure()`。链路尚未建立时也可完成 setup。
初次配置失败时，后端须回滚本次获取的硬件资源并结束回调。后端可在 `SETUP` 标记置位后
调用 `mr_eth_event_raise()`，应用在 setup 后挂接 waiter。

应用可在 setup 后重配。后端可以在配置与已启用的 Stream 冲突时返回 `-MR_EBUSY`，
合法枚举值超出平台能力时返回 `-MR_ENOSYS`。公共层仅在重配成功后保存新值。

正常 shutdown 用 `configure()` 关闭整个端口，传入的速率为 `MR_ETH_SPEED_OFF`。
配置为关闭时，后端须协调 I/O 和 IRQ，阻止新的收发，结束硬件访问，并通过 Wait 归还两路在途帧，
包括尚未挂入 DMA 的 RX 缓冲。关闭操作须允许重试和重复调用。shutdown 失败时公共层保留 Wait，
后端继续负责未归还的帧。关闭成功后，shutdown 删除 Wait，并保留下一次 setup 要应用的配置。

调用者应在删除前完成正常 shutdown。最终释放时通用驱动忽略停机错误。
如果直接进入最终释放，后端须同步停止硬件并退出所有回调，必要时复位端口。
此时驱动对象处于 dying 状态，在途帧由调用者自行处理，后端须跳过 Wait 通知。

## 3. 直接收发与硬件映射

- 将设备 MAC、MTU、速率、双工、回环、RX/TX 流控及校验和卸载映射到硬件。后端不支持的组合返回 `-MR_ENOSYS`。正常模式下 `link()` 报告 PHY 链路；回环模式下可报告本地数据路径状态；端口关闭时报告断开。
  自动协商结果及双工配置由后端管理。
- RX 每次复制或取出一帧，保留 padding 并剥离 FCS。超过帧长限制或调用者缓冲区容量时，丢弃整帧并返回
  `-MR_ERANGE`。无可交付帧时返回 0。
- TX 发送提交的帧数据，由后端或硬件补齐 padding 和
  FCS。若函数返回后硬件仍需读取帧数据，返回前复制到后端自有缓冲区。调用者传入的缓冲区在返回时即可复用。
- 后端根据两路 Stream 的启停状态选择普通收发或流式收发。普通收发也可使用后端自有缓冲区和 DMA。
  某方向的普通 I/O 与其 Stream 互斥时，后端可对该方向的普通请求返回 `-MR_EBUSY`。
  公共层处理零长度请求和基本长度校验。

## 4. Stream 与 DMA

启用 `MR_USE_DRIVER_ETH_STREAM` 后，支持的方向实现四个操作，缺少对应回调的入口返回 `-MR_ENOSYS`。
共享 MAC/DMA 启停的后端可将两路绑定。应在平台文档说明启动、状态、普通收发互斥和停流时两路帧的归还规则。

| 成员                   | 实现责任                                                                                                 |
|------------------------|----------------------------------------------------------------------------------------------------------|
| `*_stream_start(drv)` | 启用指定方向的 Stream，允许初始无帧。重复启用返回 `-MR_EBUSY` |
| `*_stream_stop(drv)` | 停止指定方向并归还其在途帧，包括等待补环的 RX 帧。允许重试和重复调用 |
| `*_stream_is_busy(drv, busy)` | 查询该方向是否启用 Stream，已启用但暂无在途帧时仍返回 `MR_TRUE` |
| `rx_stream_submit(drv, frame)` | 接受空缓冲，允许链路未建立时提交。占用有限的接收名额，可在 DMA 补环时才挂入描述符 |
| `tx_stream_submit(drv, frame)` | 端口可发送时接收待发送帧，按成功提交的顺序发送 |

两个方向都在对应的 `start` 成功后接受提交。后端在接管帧时检查该方向的状态，
未启用返回 `-MR_EPERM`。状态检查与接管帧须和停流、关闭端口同步，停流时拒绝新提交。

只有 `submit` 返回 0 才转移帧对象和缓冲区的使用权。资源满或端口暂时无法发送时返回 `-MR_EAGAIN`，
重复提交在途帧时返回 `-MR_EBUSY`。失败时保留调用者的使用权，并释放为本次提交暂时占用的资源。DMA
地址、对齐和缓存条件由后端检查。`frame.owner` 是应用上下文，后端原样保留。

描述符环可以让 DMA 连续处理已经准备好的帧。后端保存 DMA 缓冲地址或描述符与原
`frame` 的关联。收完一帧后，补环只能使用其他已提交的空缓冲。该帧从归还到再次提交期间由应用持有。
RX 启动时还没有缓冲，或运行中缓冲耗尽时，后端应在收到新的空缓冲后主动补环，
使接收能够开始或恢复。

## 5. IRQ、缓存与完成通知

移交给 DMA 前，准备缓冲区和描述符，并按平台要求完成缓存维护和写入排序。DMA
取得描述符使用权前，必须能看到完整的描述符和 TX 数据。RX 缓冲区也须满足平台对 DMA
写入及缓存行的要求。

正常收发、停流和关闭端口时，每个成功提交的帧恰好归还一次。以下顺序保证回调可安全接手缓冲区。

1. 确认硬件不再访问该帧和描述符。使用平台需要的缓存维护和内存屏障，确保 CPU 看到
   DMA 写入的数据。
2. 写入 `frame.status`，成功 RX 同时写入 `frame.size`。成功状态为
   0，硬件错误用负错误码，停机取消用 `-MR_EPERM`。
3. 解除描述符与帧的关联。释放回调提交新帧时需要获取的后端锁。
4. 调用 `mr_eth_event_raise(drv, events, frame)`。成功事件为
   `MR_ETH_WAIT_RX_READY` 或 `MR_ETH_WAIT_TX_DONE`，失败和取消分别使用对应方向的
   `MR_ETH_WAIT_RX_ERROR` 或 `MR_ETH_WAIT_TX_ERROR`。

`data` 传原始帧指针。没有对应帧的链路或引擎错误可用 `MR_NULL`
通知。已发出的帧通知不再关联后端资源，回调可以接手该帧。后端只处理应用显式提交的新工作。一个
IRQ 可以确认多帧完成，并为每帧分别分发通知。

Wait 在 `raise` 的调用上下文同步执行。IRQ
路径的回调应保持短小，正常运行时可以补交另一帧。停流和停机期间回调只回收已归还的帧。
配置、启停和删除由回调外的执行流完成，并与 I/O 串行。后端应协调 IRQ、停流和关闭端口对同一帧的回收，避免 DMA 仍在访问缓冲区、重复归还或
Wait 被销毁后仍触发通知。

## 6. HardTree 与安装

后端用 `MR_HT_COMPAT` 匹配自己的 `compatible`，为每个启用节点构造私有数据，通过
`MR_HT_DRIVER_FOREACH()` 展开实例。安装宏 `MR_HT_ETH_INSTALL(_id, _priv, _ops)`
将公共配置、私有数据和操作表绑定到驱动注册项。

| 属性         | 解释                                                                                         |
|--------------|----------------------------------------------------------------------------------------------|
| `mac`        | 必填，六字节。可用 HTC 字节串表示，例如 `mac = [02 00 00 00 00 01];`，实际地址由板级配置分配 |
| `mtu`        | 可选，1 到 1500。省略时取 `MR_ETH_MTU_MAX`                                                   |
| `speed`      | 可选，取 `mr_eth_speed_t` 对应的值，省略时取 `MR_ETH_SPEED_AUTO` |
| `duplex`     | 可选，取 `mr_eth_duplex_t` 对应的值，省略时取 `MR_ETH_DUPLEX_AUTO` |
| `loopback`   | 可选，取 `mr_eth_loopback_t` 对应的值，省略时取 `MR_ETH_LOOPBACK_NONE` |
| `flow_rx` / `flow_tx` | 可选，映射到 `flow.rx/tx` 位域，省略时关闭 |
| `csum_rx` / `csum_tx` | 可选，映射到 `csum.rx/tx` 位域，省略时关闭 |
| `status`     | HTC 据此生成注册级别。默认为 `"okay"`，设为 `"defer"` 时由应用显式 setup |

MAC 寄存器、PHY、引脚、时钟和 IRQ 的属性由实际后端定义。按真实板级资源编写 `.hts` 或
`.htsi`，通过 [HTC](../../scripts/htc/htc.md) 生成硬件描述头文件。也可用
`MR_ETH_DATA_INIT(mtu, speed, ...)` 配合 `MR_ETH_INSTALL`
手动注册设备。注册与启动级别见[通用驱动框架](../driver.md)。

## 7. 平台实现与能力边界

ETH 公共层不绑定 MAC、PHY 或 DMA 控制器。实现者应针对目标平台独立描述：MAC/PHY 配置、链路协商、普通帧收发、Stream 的帧归还、DMA 缓冲与缓存一致性、IRQ 和关机回滚顺序。

这些资源的 HardTree 私有属性与具体功能上限属于平台文档，不能反向作为所有 ETH backend 的共同限制。

## 8. 移植验收

- [ ] 配置、链路状态、整帧收发和帧边界符合公共契约。
- [ ] Stream 的提交、完成、取消和停机时缓冲区仅归还一次。
- [ ] 资源不足、关闭中和暂不支持的能力返回明确错误。
