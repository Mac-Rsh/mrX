# UART 驱动

UART 在驱动框架上统一配置、直接读写和可选 stream 操作，沿用 ADC 的
`data / priv / ops`、生命周期和 waitable 事件结构，不内置软件 FIFO。 FIFO 封装、Modbus 等上层可以直接提交各自的缓冲区。

## 配置与接入

| 项目                        | 说明                                                  |
|-----------------------------|-------------------------------------------------------|
| 头文件                      | `<mrX/drivers/uart/mr_uart.h>`，也通过 `<mrX.h>` 引入 |
| `MR_USE_DRIVER_UART`        | 默认关闭，依赖 `MR_USE_DRIVER`                        |
| `MR_USE_DRIVER_UART_STREAM` | 默认开启，依赖 UART                                   |
| 源文件                      | `drivers/uart/uart.c`                                 |
| 平台接入                    | 提供 `mr_uart_ops_t` 和硬件私有数据                   |

启用配置后使用项目工具重新生成 `mr_config.h`，不要手动修改生成头文件。 驱动 Kconfig 已通过父目录的通配 `rsource` 接入。

`mr_uart_config_t` 包含波特率、5～8 位有效数据、1/1.5/2 个停止位、 无/奇/偶校验以及 RTS/CTS 流控。每个数据元素占一个字节，有效数据位不包含
校验位。无效配置返回 `-MR_EINVAL`，平台不支持的有效配置返回
`-MR_ENOSYS`，不应静默降级。查询返回实际生效配置。

```c
mr_uart_config_t config = {
    .baud_rate = 115200,
    .data_bits = MR_UART_DATA_BITS_8,
    .stop_bits = MR_UART_STOP_BITS_1,
    .parity = MR_UART_PARITY_NONE,
    .flow_control = MR_UART_FLOW_CONTROL_NONE,
};
```

## 普通读写

- `mr_uart_read(drv, buf, size)` 读取硬件当前可用数据，不等待新数据
- `mr_uart_write(drv, buf, size)` 将数据交给硬件，允许短写
- `mr_uart_getchar(drv, &ch)` / `mr_uart_putchar(drv, ch)` 是单字节读写封装
- 返回实际字节数，失败返回负错误码；零长度请求直接返回零
- 无接收数据返回零，不表示文件结束；硬件暂时无法接收发送数据也可返回零
- 调用返回后平台不再访问传入的缓冲区
- 同方向 stream 运行时，非空读写请求返回 `-MR_EBUSY`

普通写入不承诺线路发送完成，也不触发本次写入专属的完成事件。 需要确定发送结束时机的上层应使用单次 TX stream。

## Stream

RX、TX 各自提供 `stream_start / stream_stop / stream_is_busy / stream_offset`。 公开函数以 `mr_uart_rx_`、`mr_uart_tx_`
为前缀。 每个方向最多一个 stream，两个方向可以并行；中断或 DMA 都可以实现 stream。 同一方向的操作、配置修改和关闭必须由平台正确同步，通用层没有传输锁或队列。
任一方向正在传输（包括线路仍在发送）时，配置修改返回 `-MR_EBUSY`。

### 启动与缓冲区

`stream_start(drv, buf, size, circular)` 要求非空缓冲区和非零长度。 成功返回零，仅表示已经接受任务；失败不得保留缓冲区或留下运行中的传输。
同方向忙时返回 `-MR_EBUSY`。平台要支持一个方向的 stream，必须同时提供该方向 的 start、stop、is_busy 和 offset，否则通用启动接口返回
`-MR_ENOSYS`。

调用者保持缓冲区有效直到单次传输完成或停止成功。TX 缓冲区期间不可修改； RX 缓冲区已提交区域可读取但不可修改，尚未提交区域不可读取。
循环 RX 会覆盖旧数据，消费者必须在覆盖前处理完。 平台负责 DMA 内存约束检查、缓存维护及发布顺序；无法满足时返回错误。

非循环 RX 填满后结束。重新提交另一块缓冲区可能存在接收间隙。 循环模式持续使用同一缓冲区直到停止，平台不支持该模式时返回
`-MR_ENOSYS`。 循环 TX 重复发送同一份不可修改的数据。

### 偏移与忙状态

- 非循环偏移为 `0..size`，循环偏移为 `0..size-1`
- RX 偏移表示已经写入内存、对 CPU 可见的数据边界
- TX 偏移表示已经交给硬件的字节进度，不表示线路发送进度
- 停止或完成后保留最终偏移，直到下一次成功启动
- 查询必须返回一致的快照；第一次启动前返回空闲和零偏移
- 循环偏移不记录圈数，不能单凭位置判断是否丢失整圈数据
- 非循环 TX 在最后一个停止位发出之前保持忙；循环 stream 在停止前保持忙

循环 RX 的 offset 查询不锁定数据区域。仅提供半满/全满通知和回绕位置不能保证 任意调度延迟下无损接收，上层需要控制消费延迟，不能把事件次数当作可靠字节计数。

### 停止与生命周期

`stream_stop` 幂等。成功返回时，平台必须保证硬件和 DMA 不再访问对应缓冲区， 且旧任务不会再产生通知。停止后可以查询最终偏移。停止
TX 不保证线路空闲， 硬件中已经装入的数据仍可能发送，不应据此切换 RS-485 方向。

通用初始化创建事件；反初始化依次停止 RX、TX，再删除事件。 停止失败时反初始化返回错误并保留事件，已成功停止的方向不会自动恢复。

`MR_UART_DEFINE`、`MR_UART_INSTALL`、`mr_uart_init/create/del` 以及
`mr_uart_get`/`mr_uart_put` 沿用 ADC 的管理方式。 动态创建成功后 UART 数据由驱动拥有，最终释放时调用 `mr_free`；`priv` 和
`ops`
的资源仍由平台管理。静态驱动的数据不能在动态驱动创建接口中转交。

传输或回调可能访问驱动期间必须持有驱动引用。删除前先成功停止传输，不能依赖 对象最终释放路径处理可恢复的停止失败。平台还需确保关闭时普通硬件访问已经结束，
并按自身资源管理约定处理外设时钟、引脚和中断资源。

## 事件

使用 `mr_uart_event_attach` 订阅；平台使用 `mr_uart_event_raise` 通知。 先发布状态和缓冲区内容，再发事件。回调可能位于中断上下文，不得阻塞。
先订阅再启动传输，附加到运行中的传输后还应查询当前状态，避免漏掉状态变化。

| 事件（省略 `MR_UART_WAIT_` 前缀） | 含义                                                   |
|-----------------------------------|--------------------------------------------------------|
| `RX_STREAM_HALF / RX_STREAM_FULL` | 接收缓冲区半满/全满；循环模式每圈报告                  |
| `RX_IDLE`                         | 可选的硬件接收空闲提示，不停止接收，也不代表协议帧结束 |
| `TX_STREAM_HALF / TX_STREAM_FULL` | 发送缓冲区半块/整块已交给硬件                          |
| `TX_COMPLETE`                     | 单次发送最后一个停止位已发出，缓冲区可回收             |
| `RX_ERROR / TX_ERROR`             | 对应方向发生错误                                       |

半满阈值为 `size / 2` 字节，长度为一时不产生半满事件。 平台必须保证单次 RX 完成时先置为空闲再通知 FULL，单次 TX 完成时先置为空闲再
通知 COMPLETE。循环传输的 FULL 只表示一次回绕，不归还缓冲区；循环 TX 不产生 表示整个任务完成的 COMPLETE 事件。

遇到无法继续保证数据有效性的错误，平台停止对应方向、保留有效偏移，随后报告 错误事件；另一方向可以继续工作。错误后忙状态为假不表示正常完成，上层必须结合
错误事件判断。当前接口只统一方向错误通知，不提供具体硬件错误明细查询。

FIFO 封装可以提交连续读写区域，Modbus 可以直接提交协议帧缓冲区。对于 Modbus， 协议层负责帧间隔和分帧，RS-485 正常发送结束使用
`TX_COMPLETE` 判断。

## HardTree

`MR_HT_UART_INSTALL(_id, _priv, _ops)` 与 RAM 一样，只负责安装整颗 UART 实例： 为实例定义静态 `mr_uart_data_t` 并通过
`MR_HT_DRIVER_INSTALL` 安装。平台设置
`MR_HT_COMPAT` 后，可在实例遍历中调用该宏；实例名称和初始化级别沿用驱动框架 的 HardTree 规则。

UART 没有通道或引脚这类子资源，配置作用于整颗设备，使用方直接拿
`mr_driver_t *` 调用 `mr_uart_*`。因此不提供 `mr_ht_uart_spec_t`。

## 当前实现范围

当前提供通用接口、配置校验、事件和生命周期管理；没有软件 FIFO、协议解析、 具体芯片寄存器操作或主机模拟后端。硬件收发能力由平台操作表实现。
