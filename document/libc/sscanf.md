# 格式化解析（Sscanf）

> 格式化解析模块提供 `mr_sscanf`，按格式串从字符串中提取整数、无符号数、字符与
> 字符串等字段，是格式化输出（Sprintf）的逆过程，常用于解析命令行参数与协议报文。

| 项       | 说明                                                                                                         |
|----------|--------------------------------------------------------------------------------------------------------------|
| 功能宏   | `MR_USE_SSCANF`（默认 `vsscanf` 封装）；`MR_USE_SSCANF_STD` 宏转发标准库；`MR_USE_SSCANF_3RD` 当前仅为预留项 |
| 头文件   | `<mrX/libc/mr_sscanf.h>`                                                                                     |
| 依赖模块 | C 库 `vsscanf`（内部实现直接转发）；[格式化输出](sprintf.md)（逆操作，无代码依赖）                           |
| 参考测试 | `mrX/test/libc/sscanf.c`、`mrX/test/libc/sscanf_matrix.c`                                                    |

---

## 用户指南

### 1. 模块概述

格式化解析模块解决的问题是： **以声明式的格式串从文本中提取字段，替代手写的
逐字符解析**。

特性：

- 单一入口 `mr_sscanf`；内置模式除额外的空指针前置检查外，实际解析语义由工具链 C 库
  `vsscanf` 决定。
- 参数与指针校验：输入串或格式串为 `MR_NULL` 时返回 `-1`，不崩溃。
- 支持整数、无符号、十六进制、八进制、字符、字符串与扫描集等常见转换。
- 支持赋值抑制（`*`）与字段宽度，可跳过无关字段。

需要说明的是：内置实现（`MR_USE_SSCANF`）是标准 C 库 `vsscanf` 的轻封装 （见
`mrX/libc/sscanf.c:25`），并非手写解析器——它在提供统一入口与参数校验的
同时，转换能力完全取决于工具链 C 库；这与 sprintf 模块"内置即自研解析"的 形态不同。

不适用于：内存受限到连工具链 stdio 都不愿链接的极端场合（此时请评估第三方
解析库或手写解析）；二进制数据解析（请直接按字段读取）。

### 2. 配置与依赖

| 配置项              | 类型           | 默认值 | 说明                                               |
|---------------------|----------------|--------|----------------------------------------------------|
| `MR_USE_SSCANF`     | bool（choice） | y      | 使用内置封装（`mrX/include/mrX/libc/Kconfig:126`） |
| `MR_USE_SSCANF_STD` | bool（choice） | n      | 宏转发标准库 `sscanf`                              |
| `MR_USE_SSCANF_3RD` | bool（choice） | n      | 第三方解析库预留选项；当前头文件/源码没有对应实现  |

选择 `MR_USE_SSCANF` 并重新生成 `mr_config.h` 后，包含头文件即可使用：

```c
#include <mrX/libc/mr_sscanf.h>
```

本模块无 `MR_CFG_*` 参数；运行期依赖编译器 C 库的 `vsscanf`（源文件包含
`<stdarg.h>` 与 `<stdio.h>`），目标工具链需提供该函数。

### 3. 快速上手

解析一条 "键 值" 形式的命令：

```c
#include <mrX/libc/mr_sscanf.h>

void example(void) {
    int id;
    char name[8];
    int ret;

    ret = mr_sscanf("42 hello", "%d %7s", &id, name);
    if (ret != 2) {
        /* 解析失败：仅成功赋值了 ret 个字段 */
        return;
    }
    /* id == 42, name == "hello" */
}
```

要点：

- 返回值为成功赋值的字段数，据此判断解析是否完整。
- `%s` 与扫描集必须提供足够大的缓冲，宽度（如 `%7s`）可防溢出。

### 4. 使用说明

**转换说明符**（行为由 C 库 `vsscanf` 决定，以下各项均经
`mrX/test/libc/sscanf.c` 验证）：

| 说明符               | 含义                        | 实测示例                                        |
|----------------------|-----------------------------|-------------------------------------------------|
| `%d`                 | 有符号十进制整数            | `"-42"` → `-42`                                 |
| `%i`                 | 整数（自动识别进制）        | 同标准 C                                        |
| `%u`                 | 无符号十进制整数            | `"4294967295"` → `4294967295U`                  |
| `%x`                 | 十六进制无符号整数          | `"1aF"` → `0x1AF`                               |
| `%o`                 | 八进制无符号整数            | `"755"` → `0755`                                |
| `%c`                 | 字符（不跳过前导空白）      | `"Z"` → `'Z'`                                   |
| `%s`                 | 非空白字符串（自动补 `\0`） | `"hello"` → `"hello"`                           |
| `%[...]` / `%[^...]` | 扫描集 / 反扫描集           | `"%[a-z]"` 匹配 `"hello123"` → `"hello"`        |
| `%n`                 | 记录已消费字符数            | `"12abc"` 中 `%d%n` 得 `n == 2`，不计数入返回值 |
| `%%`                 | 匹配字面 `%`                | `"100%"` 用 `"%d%%"` 解析                       |

**修饰语法**

| 语法     | 作用                   | 实测示例                                     |
|----------|------------------------|----------------------------------------------|
| 宽度数字 | 限制该字段最大消费长度 | `"%2d%d"` 解析 `"1234"` → `12`、`34`         |
| `*`      | 赋值抑制：消费但不保存 | `"%*s %d"` 解析 `"skip 9"` → `9`，返回值计 1 |
| 空白字符 | 匹配任意数量空白       | `"%d %d"` 可解析 `"  7\t8"`                  |
| 普通字符 | 字面匹配               | 不匹配则停止                                 |

**返回值约定**

- 成功：成功赋值的字段数（`%n` 不计入）。
- **输入失败**发生在第一次成功赋值之前（例如输入已经耗尽）：标准 `vsscanf` 返回
  EOF，当前常见 C 库表现为 `-1`。
- **匹配失败**（例如输入 `"abc"` 配 `%d`）在尚无赋值时返回 0；若前面已有成功赋值，则返回此前的赋值数。
- `buf` 或 `fmt` 为 `MR_NULL`：返回 `-1`。
- 空输入串 `""`：返回 `-1`；空格式串 `""`：返回 0。

### 5. API 参考

| API         | 说明                             |
|-------------|----------------------------------|
| `mr_sscanf` | 按格式串从字符串解析可变参数字段 |

**`mr_sscanf`**

```c
int mr_sscanf(const char *buf, const char *fmt, ...);
```

- `buf`：待解析字符串，`MR_NULL` 返回 `-1`。
- `fmt`：格式串，`MR_NULL` 返回 `-1`。
- `...`：与格式串对应的接收参数，均须为指针。
- 返回：直接透传 `vsscanf` 的赋值计数 / EOF 结果；`buf` 或 `fmt` 为 `MR_NULL` 时
  mrX 封装固定返回 `-1`。匹配失败可以返回
  0，而不是 `-1`。

### 6. 完整示例

示例 1：跳过前缀提取数值（赋值抑制，取材自 `mrX/test/libc/sscanf.c`）：

```c
#include <mrX/libc/mr_sscanf.h>

void extract_example(void) {
    int value;

    if (mr_sscanf("skip 9", "%*s %d", &value) == 1) {
        /* value == 9 */
    }
}
```

示例 2：扫描集提取限定字符集：

```c
void scanset_example(void) {
    char word[8];
    int rest;

    mr_sscanf("hello123", "%7[a-z]%d", word, &rest);
    /* word == "hello", rest == 123 */
}
```

示例 3：带字面分隔符的协议行解析：

```c
void proto_example(void) {
    int temp;
    unsigned humi;

    if (mr_sscanf("T=25,H=60", "T=%d,H=%u", &temp, &humi) == 2) {
        /* temp == 25, humi == 60 */
    }
}
```

更多行为（进制、宽度、空白匹配、部分赋值计数）见 `mrX/test/libc/sscanf.c`
与 `mrX/test/libc/sscanf_matrix.c`。

### 7. 常见问题（FAQ）

**Q：返回 0 和返回 -1 有什么区别？**

要区分 **input failure** 与 **matching failure**：空输入在需要转换时通常产生
EOF（现有测试为 `-1`）；`buf/fmt == MR_NULL` 被
mrX 封装直接映射为 `-1`；而第一个字段类型不匹配（如 `"abc"` 配 `%d`）返回 0。空格式串也返回
0。判断“解析是否完整成功”应直接比较返回值与期望赋值字段数。

**Q：`%c` 为什么把空格也读进来了？**

与标准 `sscanf` 一致，`%c` 不跳过前导空白；需要在 `%c` 前显式放一个空格 （`" %c"`
）来跳过空白。

**Q：`%s` 会溢出吗？**

`%s` 本身无边界保护，缓冲必须足够大；应始终加宽度限定（如 `%7s` 对 8 字节 缓冲留出
`\0` 位置）。

**Q：它和 sprintf 是同一套实现吗？**

不是。`mr_sprintf` 是自研格式化引擎，而 `mr_sscanf` 转发到工具链 C 库的
`vsscanf`，两者的自研程度不同（见第 1 节）。

**Q：为什么选择 `MR_USE_SSCANF` 还要链接 stdio？**

内置封装的转换逻辑直接复用 C 库 `vsscanf`（`mrX/libc/sscanf.c:12` 包含
`<stdio.h>`），因此工具链的 stdio 解析部分会被引入。
`MR_USE_SSCANF_3RD` 目前尚无实际代码后端；对体积敏感且只需简单解析的场合只能自行补第三方后端或使用手写解析。

## 开发者指南

### 8. 架构总览

格式化解析是 libc 中最薄的模块：一个函数、一次转发：

```
        +------------------------------------------+
        | 用户代码 / 命令解析器                      |
        +---------------------+--------------------+
                              | mr_sscanf()
        +---------------------v--------------------+
        | 格式化解析 Sscanf                          |
        |  参数校验 -> vsscanf（工具链 C 库）          |
        +------------------------------------------+
             依赖：<stdarg.h> / <stdio.h>（C 库）
```

模块自身不实现任何转换逻辑；`MR_USE_SSCANF_STD` 时头文件直接宏转发标准库
`sscanf`，`MR_USE_SSCANF` 时调用同一工具链 C 库的
`vsscanf` 并增加 `buf/fmt` 空指针检查。正常格式解析行为因此主要来自 C 库；不要把
mrX 文档中的测试结果理解成跨所有 libc
实现完全固定的扩展行为。

### 9. 数据结构

无。模块不定义任何类型或全局状态；`mr_sscanf.h` 在内置模式下也不引入额外 类型（
`mr_sscanf.h:13-15`，`MR_USE_SSCANF_STD` 时包含
`<stdio.h>`，内置模式 无额外包含，源文件自行包含 `<stdarg.h>` / `<stdio.h>`）。

### 10. 核心流程

`mr_sscanf`（`mrX/libc/sscanf.c:14`）的完整实现：

1. 参数校验：`buf` 或 `fmt` 为 `MR_NULL` 返回 `-1`（`sscanf.c:19`）。
2. `va_start` 取出可变参数，直接调用 C 库 `vsscanf(buf, fmt, args)`
   （`sscanf.c:25`）。
3. `va_end` 后返回 `vsscanf` 的结果（赋值字段数或 EOF）。

设计取舍：解析器是格式化家族中体积与边界情况最多的部分（扫描集、宽度、
`%n`、进制前缀等），直接复用经过充分验证的 C 库实现可以以最小代码量获得
标准语义；统一入口与参数校验则由本模块补齐，供上层以
`mr_` 前缀 API 调用。

### 11. 并发与中断安全

- mrX 这一层本身只维护栈上的 `va_list` 与返回值，没有自己的全局解析状态。
- 真正的解析由工具链 `vsscanf` 完成；其内部是否使用 locale、锁、堆或其他 libc 状态由具体
  C 库实现决定，mrX
  不能统一承诺线程/中断安全，也不能断言解析复杂度仅与输入长度线性相关。
- 接收参数的类型、大小与格式串必须匹配，所指存储须在调用期间有效；这些可变参数约束无法由封装检查。

### 12. 扩展与派生

本模块没有对象 clazz，也没有注册式回调或自定义说明符接口；扩展面是
**编译期后端选择**：

- **后端选择**：`MR_USE_SSCANF` 使用模块内置封装（默认），`MR_USE_SSCANF_STD` 把 API
  整体 转发标准库 `sscanf`（
  `mrX/include/mrX/libc/mr_sscanf.h:27-28`）。两者互斥参与编译，
  切换后端只改变实现来源，不改变调用方式。
- **第三方后端**：`MR_USE_SSCANF_3RD` 已在 choice 中定义（
  `mrX/include/mrX/libc/Kconfig:121`）， 但头文件目前只有上述两个分支，代码中没有任何
  `MR_USE_SSCANF_3RD` 分支——该选项是预留位， 当前不存在可用的第三方解析库接入路径。
- **新增说明符**：本模块不做格式解析，解析能力完全来自所选后端的 `vsscanf`。要支持标准库
  之外的说明符，只能在第三方后端分支中接入，不能通过回调或注册表扩展。

与 [格式化输出 Sprintf](sprintf.md) 的差异：sprintf 的输出可经 `mr_snprintf`
组合封装， 而 sscanf
的解析结果只能通过调用方传入的指针返回，没有可供上层拦截的中间层。
